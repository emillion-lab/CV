Product

🤖 How this gets built

All of this ships alongside a full-time operations job, in a few hours a week. That is only possible because the entire delivery loop runs through an AI pair-developer wired directly into my repositories. Not "AI wrote some code" — a working method with its own tooling, guardrails and cost discipline.

Chat (phone or desktop)→Self-built MCP connector→GitHub repo→Patch workflow→Cloudflare / Pages

The tooling

  • A Cloudflare Worker I wrote myself exposes GitHub to the model over MCP — read, patch, commit and dispatch workflows straight from a chat window
  • A persistent context repository the model reads at the start of every session: architecture, deploy paths, decisions taken and known landmines
  • The result is a complete development loop that runs from a phone in a parked car

The guardrails

  • Diagnosis before code — logs, diffs and live endpoints first, model second
  • Targeted patches against exact anchors, never full-file rewrites
  • Syntax gate before every deploy; rebase-and-retry on concurrent pushes
  • Deploys are always explicit — nothing reaches production as a side effect

The economics

  • Every task is routed to the cheapest model that can actually do it — mechanical edits, routine fixes, multi-file debugging and greenfield architecture each get a different tier
  • The same discipline I apply to service delivery: match the resource to the demand, measure it, and don't pay for capacity you don't need

This is the direction I want to bring into an operations role — AI applied to incident intelligence, knowledge management and service automation, by someone who has already built and run the pipeline rather than only read about it.
